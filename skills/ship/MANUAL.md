# Manual: Ship Skill

---

#### 🇺🇸 English
**What it does:**
This skill runs the complete RTK release cycle: build verification, version bump, git tag, and push to trigger CI/CD. Invoke it when a version is ready to go out, or right after finishing a feature and before tagging.

**Key Features:**
- **Verifies Before It Ships:** Formatting, zero clippy warnings, full test suite, performance benchmarks (<10ms startup, <5MB resident), integration tests, and a clean working tree — all checked before anything is tagged.
- **Semver by Change Type:** New filter or command → MINOR. Bug fix or performance work → PATCH. Breaking CLI change → MAJOR. With concrete RTK examples for each.
- **CHANGELOG Is Hands-Off:** It's auto-generated by release-please from conventional commits. Editing it manually is what creates the rebase conflicts documented in Common Issues.
- **Tag Carries the Notes:** The annotated tag holds the changelog excerpt and the performance line, so the GitHub release reads correctly without extra work.
- **Post-Release Verification:** Watch the Actions run, confirm the release exists with binaries and checksums attached, and install from the published artifact to confirm the version reports correctly.
- **Three Rollback Paths, Ranked:** Patch release (preferred) → `cargo yank` (crates.io only) → revert the tag (last resort, with the exact delete-local/delete-remote/delete-release/revert sequence).
- **Security Pre-Flight:** No secrets, no committed `.env`, `cargo audit` clean, shell injection and cross-platform escaping reviewed — before the tag, not after.

**Optional:** `scripts/ship.sh <version>` automates checks → version bump → build → commit → tag → push in one command.

#### 🇧🇷 Português
**O que faz:**
Esta skill executa o ciclo completo de release do RTK: verificação de build, bump de versão, tag git e push para disparar o CI/CD. Invoque quando uma versão está pronta para sair, ou logo depois de terminar uma feature e antes de tagear.

**Principais Recursos:**
- **Verifica Antes de Enviar:** Formatação, zero warning do clippy, suíte de testes completa, benchmarks de performance (<10ms de startup, <5MB residente), testes de integração e working tree limpa — tudo checado antes de qualquer tag.
- **Semver por Tipo de Mudança:** Filtro ou comando novo → MINOR. Correção de bug ou performance → PATCH. Mudança quebrando a CLI → MAJOR. Com exemplos concretos do RTK para cada caso.
- **CHANGELOG Não Se Toca:** É gerado automaticamente pelo release-please a partir dos conventional commits. Editar na mão é o que cria os conflitos de rebase documentados em Common Issues.
- **A Tag Carrega as Notas:** A tag anotada guarda o trecho do changelog e a linha de performance, então o release do GitHub sai legível sem trabalho extra.
- **Verificação Pós-Release:** Acompanhar o run do Actions, confirmar que o release existe com binários e checksums anexados, e instalar a partir do artefato publicado para confirmar que a versão reportada bate.
- **Três Caminhos de Rollback, Ranqueados:** Patch release (preferido) → `cargo yank` (só crates.io) → reverter a tag (último recurso, com a sequência exata de deletar local/deletar remoto/deletar release/reverter).
- **Pré-Voo de Segurança:** Sem segredos, sem `.env` commitado, `cargo audit` limpo, injeção de shell e escaping cross-platform revisados — antes da tag, não depois.

**Opcional:** `scripts/ship.sh <versão>` automatiza checks → bump → build → commit → tag → push num comando só.
